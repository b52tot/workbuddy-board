# 分发与部署

> 产物：`dist/BoardWidget.exe` —— **13.65 MB，单文件，完全自包含**
> 拷到任何 Win10+ 电脑，双击即用。**不需要装 Python、不需要装看板服务、不需要数据库。**

---

## 目标机需要什么

| 依赖 | 要不要 | 说明 |
|---|---|---|
| Python | ❌ **不用** | 已打进 exe |
| **看板服务** | ❌ **不用** | **已打进 exe**，启动时自动拉起 |
| 数据库 | ❌ **不用** | 首次运行自动建库 |
| VC++ 运行库 | ❌ **不用** | 产物自带 `VCRUNTIME140.dll` + `api-ms-win-*` |
| .NET | ❌ **不用** | 本方案全程未用 .NET |
| **WebView2 运行时** | ✅ **唯一的硬依赖** | 见下 |

**WebView2**：Win11 自带；Win10 装了 Edge 的通常也有。
没有的话，启动时会**弹说明框**告诉你怎么装（不是崩、不是白屏）。

**自检**（不开窗口）：
```cmd
BoardWidget.exe --check      :: 查 WebView2
BoardWidget.exe --selftest   :: 查内置服务能否起来、数据能否读
```

## 怎么部署到别的电脑

**只有一步：把 exe 拷过去，双击。**

它自己会：

1. 检查 WebView2（缺了给指引）
2. **拉起内置看板服务**（先探 127.0.0.1:8791，有人跑就用现成的、绝不抢占；没有就起内置的）
3. **首次运行建库**（默认四列：待办 / 进行中 / 阻塞 / 已完成）
4. 开窗口显示任务
5. 自动开启开机启动（托盘菜单可关）

**运行数据**（数据库、配置、窗口状态）落在 **exe 同目录**；
该目录不可写时（比如装在 `Program Files`）自动回落到 `%APPDATA%\WorkBuddyBoardWidget`。

---

## 别的电脑上是空库，怎么加任务？

**看板页面就是管理入口**：点挂件顶栏的 **`↗`**，会打开浏览器里的完整看板。

内置服务**开放了写入**（`allow_write: true`）。这一条是特意改的：

> 项目里别处的默认是 `false`（看板当纯展示用）。
> 但**自带服务的独立版不一样** —— 它是空库起步，而挂件本体只读，
> 看板页面是这个包里**唯一**的管理入口。
> 若也禁写，用户拿到手就是个永远空着的窗口，**没法用**。
> 服务只监听 `127.0.0.1`，风险面限于本机。

## 为什么之前"拷过去没用"

**这是我犯的架构错误，值得写下来。**

第一版只打包了挂件界面，**看板服务留在了项目目录里**。结果：

- 本机跑：一切正常（因为项目就在旁边）
- **拷到别的电脑**：那台机器没有 `svc.py`、没有 Python、没有数据库
  ⇒ 挂件永远显示「连不上」⇒ **那不叫分发，叫半成品**

**修法**：把看板服务（`board/` + `server/` + `web/`）一起打进 exe。

**代价极小**：看板服务**只用 Python 标准库**（`sqlite3` / `http.server` / `json`…），
全部代码约 300KB —— exe 从 12.89MB 只涨到 **13.65MB**。

---

## 打包时踩的坑（都会让"打包成功但运行失败"）

这三个坑的共同特征：**打包不报错，运行才炸，而且现象都伪装成"连不上"**。

| 坑 | 现象 | 修法 |
|---|---|---|
| **`board/schema.sql` 没打进去** | 服务线程抛 `FileNotFoundError` 挂掉，主程序继续跑 ⇒ 界面显示"连不上" | PyInstaller **只打 `.py`**，`.sql` 是数据文件，必须显式 `add-data` |
| **`board`/`server` 是函数体内 import** | `ImportError`，服务起不来 | 静态分析看不到 ⇒ 必须写进 `hiddenimports` |
| **数据库落到临时目录** | 数据"莫名其妙丢了" | 打包后 `PROJECT_ROOT` 指向 `_MEIPASS`（临时解压目录）⇒ 配置必须放可写目录，让 `base_dir` 自动推导正确 |

**排查方法**：`--selftest` 会打印服务起没起、库在哪、能不能取到数。
光看"窗口能不能开"是查不出来的 —— 界面从来都能开，问题在数据端。

## 体积

| 版本 | 体积 | 说明 |
|---|---|---|
| 诊断版（含 numpy + PIL 全量） | 70 MB | 瘦身前 |
| 只打挂件界面 | 12.89 MB | **不能分发**（缺服务） |
| **当前（自包含）** | **13.65 MB** | ✅ 拷过去就能用 |

瘦身手段（`boardwidget.spec` 里都有注释）：
- 排除 numpy（约 32MB，挂件不碰数值计算）
- 排除 Pillow 的编码器（只留 PNG/ICO，托盘图标用）
- **UPX 压缩**（无损，只压字节）—— 需把 `upx.exe` 加进 `PATH`

**还有 9.1MB 的 `libcrypto`/`libssl` 保留着** —— 那是 Python `ssl` 的依赖，
拉 `http://` 用不到，但配 `https://` 看板就需要。要省可以砍，代价是只能 http。

## 连远程看板（可选）

默认用内置服务（`127.0.0.1:8791`）。若想连别的机器上的看板，
在 **exe 同目录**放 `host_config.json`：

```json
{
  "board_url": "http://192.168.30.121:8791",
  "board_root": "\\\\192.168.30.121\\share\\workbuddy-board"
}
```

- `board_url` — 数据来源。填了它，**内置服务就不会启动**（先探到有服务就用现成的）
- `board_root` — 看板项目位置。**仅当** `board_url` 不通、想让它去拉起远程服务时才需要

跨机访问要让看板服务监听 `0.0.0.0` 并放通端口。
本服务的 CORS 只放行 `127.0.0.1` / `localhost` 来源 —— 跨机场景下需要自行调整。

## 自己重新打包

```cmd
cd widget
pip install pyinstaller pystray pillow pywebview
python make_icon.py                      :: 重新生成图标（可选）
set PATH=<upx解压目录>;%PATH%             :: 想用 UPX 压缩就加这行
pyinstaller --noconfirm boardwidget.spec
```

> ⚠️ **不要加 `--clean`**：它要清理 PyInstaller 缓存（几十个文件），
> 在受管环境下会触发批量删除保护、**导致整个命令中止而 exe 没重建**。
> 打包后**务必核对 exe 与源码的时间戳** —— 只看命令退出码会以为成功了。

产物在 `dist/BoardWidget.exe`。
