# 桌面挂件 · 使用与验证

> 第一轮产出。宿主用 **Python + pywebview（WebView2 后端）**，
> 内容层就是已经定稿的 `widget.html` / `widget.css` / `widget.js`。

---

## 怎么启动

**双击 `start.cmd`**。

（它会用 `pythonw.exe` 起，不带黑框；找不到 venv 时回落到系统 `pythonw`。）

启动后你会看到：一个无边框、常驻最前的窄条窗口，显示看板上的任务。

---

## 操作

| 想做什么 | 怎么做 |
|---|---|
| **移动窗口** | 拖**顶栏**（标题那一行） |
| **改大小** | 拖**右下角斜纹**手柄 |
| **调透明度** | 点底栏 `⚙` → 透明度滑块 |
| **换布局** | 点底栏 `⚙` → 紧凑 / 宽松 / 卡住优先 |
| **看任务详情** | **点卡片**（看变更流水） |
| **收起 / 展开** | 点顶栏的 `—` |
| **打开完整看板** | 点顶栏的 `↗` |
| **关闭挂件** | 点底栏的 `✕` |

**位置和尺寸会被记住**，下次启动原样恢复。

## 遇到问题怎么查

### ① 窗口起来了但显示"加载 widget.js 失败"

说明 **`host.html` 和 `widget.js` 不在同一目录**。

这不是猜测——**第一轮就踩了这个坑**：宿主页面原本放在 `widget/host/` 下，
而 pywebview 的服务根目录 **= 传给它的那个 URL 所在目录**（读它源码确认的）：

```python
common_path = os.path.commonpath(local_urls)
server.root_path = abspath(common_path)
return bottle.static_file(file, root=server.root_path)
```

所以 `host/host.html` 里的 `../widget.js` **出不去那个根**，必然 404。
现在 `host.html` 与 `widget.js` 同级，正常不该再触发。
若仍出现，页面会**直接显示当前 URL**，照它看是哪个目录。

### ② 窗口显示"看板服务未启动"

挂件连不上 `127.0.0.1:8791`。三种可能：

- 看板服务没起 → 项目根跑 `python svc.py start`
- 地址不对 → 改 `widget/host_config.json` 里的 `board_url`
- 服务在但端口变了 → 同上

**注意**：这个状态和一整屏空白是**两回事**，页面会明确区分。

### ③ 想知道内部发生了什么

```cmd
python host.py --debug
```
会打开 WebView2 的开发者工具，能看到 console、网络请求。

### ④ 窗口跑到屏幕外看不见了

`host.py` 启动时会**把位置夹回可见区域**（防止拔掉显示器后窗口驻留在不存在的坐标）。
实在不行删掉 `widget/state.json`，下次启动回到默认位置。

## 宿主做了什么、没做什么

**做**：
- 无边框、置顶、可拖、可缩放、位置记忆
- 拉 `/api/board`（带 **ETag/304**：内容没变时不重复传整包）
- 连不上时**退避重试**（2→4→8→…→60s），并切到明确的"连不上"视图
- 收起态轮询降频到 12s（省流）

**不做**（刻意的）：
- **不写数据**。建卡/移卡一律走看板的 MCP 工具 —— 挂件是只读的，
  这是既有设计（`allow_write=false`），也是"挂件不该有写权限"的取舍。
- **不自己算停滞**。用后端给的 `stalled_ids` —— 两边各算一套必然会不一致。

## 技术选型的来历

| 候选 | 结论 |
|---|---|
| **WPF + WebView2** | ❌ 本机**没有 .NET SDK**（只有运行时）⇒ 不能 `dotnet build`；且 `csc.exe` **已被沙箱拦**（"compiles arbitrary C# code"） |
| **Rust / Tauri** | ❌ `rustc`/`cargo` 全无，**MSVC 链接器也没有**；且 `cargo build` 与 `csc.exe` 同属"编译任意代码"，沙箱大概率同样拦 |
| **Python + pywebview** | ✅ **选用**。WebView2 运行时本机已有（154.0.4258.53），零编译，能直接复用已定稿的 HTML/CSS |

**关键点**：三个方案的**内容层完全一样**。将来若要做成单文件 exe 分发，
只需换宿主，`widget.js` / `widget.css` **原样搬过去**。
